# 專案總結與實作指南

## 1. 專案 Spec 總結
- **核心目標**: 有效過濾並清理 Google Takeout 導出的 AI Mode 對話紀錄。
- **處理流程**:
  - **解析**: 將 Unicode 轉義的原始 JSON 資料處理為可視化格式。
  - **人機協作**: 提供 UI 讓使用者標記保留或刪除項目。
  - **自動化**: 利用 Playwright 模擬手動操作 Google My Activity 介面進行刪除。
- **關鍵限制**: 使用 Headful 模式以保持登入狀態，刪除過程必須實施速率限制。

## 2. 實作架構優化建議
- **Job Queue 管理**: 刪除邏輯應封裝為 Queue，並維護每個項目的狀態 (Pending/Done/Failed)。
- **狀態持久化**: 使用 `state.json` 追蹤進度，確保程式在崩潰或中斷後可無縫重啟。
- **Dry Run 模式**: 在真實操作前，必須具備「模擬刪除」功能以供使用者核對清單。
- **組態抽離**: 將重試機制 (Retry Policy) 與執行延遲 (Jitter) 參數化至 `config.json`。

## 3. Lessons Learned (實作經驗)
- **選擇器穩定性**: Google 網頁結構常變動，應優先使用 `data-` 屬性或 Aria Labels，而非依賴易變動的結構路徑。
- **反機器人防禦**: 過快的操作會觸發 Captcha，必須引入隨機化間隔 (Jitter) 來降低觸發風險。
- **解析健壯性**: 深入處理轉義字元是 UI 呈現品質的關鍵。
- **人為判斷優先**: 對於刪除類的操作，保留「人類檢查」環節 (Human-in-the-loop) 是保障資料安全的最高原則。
